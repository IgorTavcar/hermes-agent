Hermes Agent — Engineering Wiki

Hermes Agent is a self-improving, multi-platform AI agent harness from Nous Research (MIT-licensed) that drives a single user message to completion through a provider-agnostic turn loop, calls real tools over an RPC stub so a fifty-step pipeline costs one inference turn, and runs against roughly two dozen inference providers — including subscription-OAuth backends like ChatGPT Plus and Claude Pro/Max — while clinging to the two things that actually matter in production: the model's context window and its hourly rate quota.

What Hermes is

Hermes is the agent runtime that wraps a chat model in everything it needs to act in the world: a terminal, a filesystem, web search, code execution, memory, and a gateway onto messaging platforms. It is provider-agnostic by design. The same production turn loop, AIAgent.run_conversation() at run_agent.py:8169, is used identically by the CLI and the gateway, and it speaks to every backend through the OpenAI ChatCompletion spec plus an Anthropic Messages transport, with adapters for Codex Responses and Bedrock Converse. Provider differences are quarantined inside _build_api_kwargs and per-provider adapter modules so the loop body stays uniform.

That loop is deliberately simple at its core — a synchronous, single-threaded while (api_call_count < max_iterations and iteration_budget.remaining > 0) at run_agent.py:8531 — and deliberately paranoid at its edges. Each iteration assembles per-call api_messages (an ephemeral system prompt plus memory and plugin injections plus KV-cache breakpoints), calls the model through a streaming-first interruptible transport, normalizes whatever the provider returns into a uniform OpenAI-style SimpleNamespace, and branches on tool-calls-versus-text. Tool calls dispatch through _execute_tool_calls() at run_agent.py:7235, which runs them on a concurrent ThreadPoolExecutor (up to 8 workers) or sequentially, appends role:"tool" results, and continues; a plain text response with no tool calls becomes the final_response and breaks.

Key insight. There are genuinely two loop implementations, and they are asymmetric. The production sync run_conversation is shared verbatim by CLI and gateway; the only truly distinct second loop is the async HermesAgentLoop.run() at environments/agent_loop.py:175, used solely by RL and eval environments against a pluggable server — and it even carries a raw <tool_call>-tag fallback parser (environments/agent_loop.py:268) for servers whose structured tool-calling can't keep up.

"Self-improving" is not a slogan here. Hermes closes a learning loop: trajectories are compressed and fed back, routines run on cron, and an auxiliary guardian LLM sits inside the approval gate to triage approve/deny/escalate before a human is ever bothered (tools/approval.py:766), an idea borrowed from OpenAI Codex's Smart Approvals.

Highlights at a glance

The recurring theme across Hermes is that the non-obvious win is almost always about protecting the LLM's context window, surviving real-world rate limits, or making stateless cloud backends behave like stateful shells.

Surprising by design. Streaming is preferred always — even when no display or TTS consumer is attached — purely to gain stale-connection and read-timeout health checks the non-streaming path lacks (run_agent.py:8844). The streamed response is then repackaged into a non-streaming-shaped SimpleNamespace so the loop body never notices.
Cache-friendly by construction. Tool-call JSON is re-serialized with sort_keys and tight separators on every API call (run_agent.py:8696) to keep the prompt prefix byte-identical across turns, preserving KV-cache reuse on local inference servers like llama.cpp, vLLM, and Ollama.

  U[User message]-->RC[run_conversation run_agent.py:8169];
  RC-->L{budget loop 8531};
  L-->A[assemble api_messages + cache breakpoints];
  A-->T[streaming-first transport];
  T-->N[normalize to SimpleNamespace];
  N-->B{tool calls?};

Caveat. Subscription-OAuth providers route real consumer subscriptions through agent traffic (e.g. Claude Pro/Max via Bearer auth with Claude-Code identity, ChatGPT Plus driving Codex). Confirm such usage is within each provider's terms of service before relying on it in production; Hermes provides the transport, not the entitlement.
