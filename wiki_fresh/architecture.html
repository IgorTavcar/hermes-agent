Architecture & Internals

Hermes is a set of thin drivers wrapped around exactly one agent core: the AIAgent class and its single production turn loop. The CLI, the TUI, the multi-platform gateway daemon, the cron scheduler, the ACP adapter and the batch runner all feed the same loop — they differ only in how messages get in and how replies get out. This page maps that core, the gateway that fronts it, the SQLite state layer beneath it, and the internals of how agents spawn, steer and talk to each other.

One shared core

The only agent class is AIAgent at run_agent.py:412. Its constructor (run_agent.py:435) and its public turn method run_conversation() (run_agent.py:8339) are thin forwarders into the agent/ package: real construction happens in agent/agent_init.init_agent() (agent/agent_init.py:493) and the real loop is agent/conversation_loop.run_conversation() (agent/conversation_loop.py:1704). There is no second code path — every surface below drives this one function.

Key insight. The loop head is a plain synchronous while (api_call_count < agent.max_iterations and agent.iteration_budget.remaining > 0) or agent._budget_grace_call at agent/conversation_loop.py:1922. Everything else in the repo is scaffolding to feed, protect, persist, and observe that loop. The loop itself is dissected on the Turn Loops page.

Gateway: inbound path

The gateway controller is GatewayRunner at gateway/run.py:6547. Platform adapters subclass BasePlatformAdapter (gateway/platforms/base.py:2890); built-ins live in gateway/platforms/, plugin platforms register through PlatformRegistry (gateway/platform_registry.py:232), and the Platform enum even fabricates pseudo-members for plugin platforms via _missing_() (gateway/config.py:348).

A message travels through a strictly ordered pipeline:

  1. Normalize. The adapter converts a platform update into a MessageEvent (gateway/platforms/base.py:2300) carrying a SessionSource (gateway/session.py:149) and calls handle_message() (gateway/platforms/base.py:5981).
  2. Key. build_session_key(...) is derived right at the adapter boundary (gateway/platforms/base.py:6006).
  3. Gate. A per-session busy guard (_active_sessions, gateway/platforms/base.py:6033) either dispatches, merges the message into a pending FIFO (gateway/platforms/base.py:6163), or — for /stop, /new, /reset — interrupts then dispatches (gateway/platforms/base.py:6056).
  4. Spawn. _start_session_processing() installs the guard and creates an asyncio task per message (gateway/platforms/base.py:5817).
  5. Route. The installed handler is GatewayRunner._handle_message (gateway/run.py:16237): reset inherited context vars (gateway/run.py:16265), resolve profile route (fail-closed, gateway/run.py:16289), run the pre_gateway_dispatch plugin hook before auth (gateway/run.py:16334), then auth/pairing, slash commands, and finally _handle_message_with_agent (gateway/run.py:18574).
  6. Resolve session. SessionStore.get_or_create_session (gateway/session.py:2535), a durable active-turn marker (gateway/run.py:18344), and a cross-process per-session-id turn lease (gateway/turn_lease.py:152).
  7. Run. _run_agent_inner (gateway/run.py:27763) builds a TurnRunner (gateway/run.py:4160) and submits the blocking turn to the thread pool (gateway/run.py:28726); TurnRunner.run_sync resolves or creates the cached AIAgent and calls agent.run_conversation(...) (gateway/run.py:6272).

Session keying — the exact rules

Single source of truth: build_session_key() at gateway/session.py:1090, prefixed by a namespace from _session_key_namespace() (gateway/session.py:1070) — agent:main for the default profile, agent:<profile> when multiplexing.

  • DMs: <ns>:<platform>:dm[:scope_id][:chat_id][:thread_id], falling back to the sender's user id when there is no chat id — the explicit anti-cross-user-bleed guard (gateway/session.py:1149).
  • Groups/channels/threads: chat-type keyed, with per-user isolation in groups on by default (group_sessions_per_user=True, gateway/session.py:1092) while threads are shared by default (gateway/session.py:1200).
  • WhatsApp JID/LID identifiers are canonicalized on both sides (gateway/session.py:1140); Discord auto-thread continuity hashes the channel-initiating message and its thread follow-ups to the same key via prospective_thread_id (gateway/session.py:1177).
So: sessions are per (profile, platform, chat, thread — and, in groups only, per user). Not simply per-user, not simply per-channel.

Session store & the state DB

SessionStore (gateway/session.py:1245) keeps routing metadata and transcripts in SQLite via SessionDB, falling back to legacy JSONL if SQLite is unavailable. It is synchronous and lock-guarded; the event loop reaches it through AsyncSessionStore, a __getattr__ proxy that wraps every call in asyncio.to_thread (gateway/session.py:1221). The routing record is SessionEntry (gateway/session.py:777): session_key → session_id plus origin, token/cost counters, suspension and model-override fields, persisted both to sessions.json and to the gateway_routing table (hermes_state_common.py:373).

The database itself is ~/.hermes/state.db (hermes_state.py:379; home resolved by get_hermes_home(), hermes_constants.py:114), owned by SessionDB (hermes_state.py:3093) with schema version 26 (hermes_state_common.py:219) and DDL at hermes_state_common.py:249:

Writes flow from AIAgent._persist_session (run_agent.py:1926) through a sequence-repair step that fixes user;user alternation wedges (run_agent.py:2019).

Gateway: outbound path

Two distinct paths carry output back to the user:

  • Streaming, during the turn. GatewayStreamConsumer (gateway/stream_consumer.py:156) is the single sink for typed events defined in gateway/stream_events.py:44 (MessageChunk plus tool/lifecycle events). The contract is explicit: "smart agent emits structured data, smart gateway decides delivery" — and stream events are presentation-only, never persisted to history (gateway/stream_events.py:26).
  • Final reply / cron / notifications. DeliveryRouter.deliver() (gateway/delivery.py:318) fans out over DeliveryTargets parsed from strings like origin, telegram, telegram:123456:789 (gateway/delivery.py:231), with a DeadTargetRegistry short-circuiting unreachable chats (gateway/delivery.py:340).

The handler return contract: Optional[Union[str, EphemeralReply]] — None means "already delivered via streaming" (gateway/platforms/base.py:2782); stale replies are suppressed when the session was interrupted mid-turn (gateway/platforms/base.py:6297).

Context management

Context handling is pluggable behind ContextEngine(ABC) (agent/context_engine.py:89) with the lifecycle contract on_session_start → update_from_response → should_compress → compress → on_session_end. The default engine is ContextCompressor (agent/context_compressor.py:1848), whose documented algorithm is:

  1. prune old tool results (no LLM call),
  2. protect the head (system prompt + first exchange),
  3. protect the tail by token budget (~20K, agent/context_compressor.py:2099),
  4. summarize the middle with a structured LLM prompt,
  5. iteratively update that summary on later compactions.

Durable anti-thrash guards persist compression-failure cooldowns and ineffective-compression streaks across restarts (agent/context_compressor.py:2414, agent/context_compressor.py:2350), and there is a micro-compaction rolling-summary path (agent/context_compressor.py:1899). In-place compaction does not rotate the session id — the gateway re-baselines transcripts when it sees agent._last_compaction_in_place (gateway/run.py:6318).

Don't confuse the two compressors. trajectory_compressor.py at the repo root (trajectory_compressor.py:332) is offline dataset post-processing for training-data trajectories — it pairs with batch_runner.py, not with live context management.

Subagents: delegate_task

Delegation is a tool the model calls: delegate_task(...) at tools/delegate_tool.py:3597, dispatched agent-side through AIAgent._dispatch_delegate_task (run_agent.py:8214). The central policy lives right there:

_is_subagent = getattr(self, "_delegate_depth", 0) > 0
return _delegate_task(..., background=(not _is_subagent), parent_agent=self)

Top-level delegations always run in the background; a delegation issued by an orchestrator subagent stays synchronous, because the orchestrator needs results inside its own turn and does not own the gateway session an async result would route back to (run_agent.py:8226). The model-facing background parameter is deliberately ignored (run_agent.py:8236).

Child construction & isolation

_build_child_agent() (tools/delegate_tool.py:1578) constructs a real AIAgent with:

  • Depth/role: child_depth = parent._delegate_depth + 1; role degrades to leaf unless orchestration is explicitly allowed, and leaf children have delegate_task stripped from their toolset (tools/delegate_tool.py:1278).
  • Toolsets: inherited and intersected, never expanded — "subagent must not gain tools the parent lacks" (tools/delegate_tool.py:1660).
  • Context: an ephemeral child system prompt (tools/delegate_tool.py:1173) with skip_context_files=True, skip_memory=True, platform="subagent", quiet_mode=True (tools/delegate_tool.py:1950).
  • Persistence: each child gets its own dedicated SessionDB handle at the parent's db path — so a parent teardown can't close it under a background child — with lineage via parent_session_id (tools/delegate_tool.py:1900).
  • Identity: subagent_id = "sa-<idx>-<uuid8>", plus a weakref back to the parent used for ownership checks (tools/delegate_tool.py:1998).
  • Worktree isolation (opt-in): each child can get its own git worktree branched from HEAD (tools/delegate_tool.py:887).
  • Approvals: subagents run under auto-approve/auto-deny callbacks, never an interactive prompt (tools/delegate_tool.py:78).

Fan-out and result return

_execute_and_aggregate() (tools/delegate_tool.py:3890) runs a single task inline; N tasks fan out on a DaemonThreadPoolExecutor with per-child contextvar copies (tools/delegate_tool.py:3921), polled with wait(timeout=…) instead of as_completed() so a parent interrupt can abandon wedged children (tools/delegate_tool.py:3939). Each child ultimately calls child.run_conversation(user_message=goal, …) (tools/delegate_tool.py:2791). Limits: max concurrent children default 10 (tools/delegate_tool.py:846), spawn depth default 1 — flat parent→child (tools/delegate_tool.py:973).

Synchronous path: the aggregate dict — per-task status, summary, api_calls, exit_reason, tokens, tool_trace — is JSON-serialized as the tool result (tools/delegate_tool.py:4329), with a summary byte-budget that spills to file when exceeded (tools/delegate_tool.py:2371).

Background path: dispatch_async_delegation_batch() (tools/async_delegation.py:1015) occupies one async slot for the whole fan-out and returns {"status": "dispatched", "delegation_id": …} immediately — the model is told not to wait or poll (tools/delegate_tool.py:4265). On completion, _push_completion_event persists to the async_delegations table and enqueues onto process_registry.completion_queue (tools/async_delegation.py:1006, queue at tools/process_registry.py:455). Consumers: the gateway's _async_delegation_watcher (gateway/run.py:25485), which coalesces same-session completions into one synthetic turn with durable claim/ack so nothing double-injects (gateway/run.py:25424), and the CLI's idle drain (cli.py:19481).

Both paths converge in _finalize_child_results (tools/delegate_tool.py:3403): summary budget → parent memory-manager on_delegation(...) → subagent_stop plugin hook per child → child-cost rollup onto the parent session.

Live agent-to-agent I/O

  • Parent → child steering: steer_subagent() (tools/delegate_tool.py:290) resolves the live registry record and calls AIAgent.steer(text) (run_agent.py:3381), which appends the text to the child's last tool result at its next iteration boundary — the in-flight tool call is never cut. A steer that wins the race after the last delivery boundary is drained into the completion entry as missed_steer (tools/delegate_tool.py:309).
  • Parent → child interrupt: cooperative flag, recursing into grandchildren; hard interrupt on timeout (tools/delegate_tool.py:266, tools/delegate_tool.py:2814).
  • Child → parent progress: _build_child_progress_callback (tools/delegate_tool.py:1338) relays child tool events with subagent_id, parent_id, depth, model and toolsets threaded through, so a UI can reconstruct the live spawn tree; gateway mode batches tool names, CLI mode prints tree lines.
  • Child text streaming: children stream via stream_callback=_relay_child_text (tools/delegate_tool.py:2794).
  • Model-facing control plane: delegate_task(action="list"|"steer"|"stop") (tools/delegate_tool.py:466), ownership enforced by walking the parent weakref chain (tools/delegate_tool.py:380).
  • Operator control plane: global spawn pause switch (tools/delegate_tool.py:194) driven from the TUI /agents panel.
  • Plugin-safe API: agent/subagent_lifecycle.py exposes immutable contracts and HMAC-authenticated handles instead of raw AIAgent objects (agent/subagent_lifecycle.py:37).

execute_code: RPC tool calls from Python scripts

The signature Hermes trick for collapsing multi-step pipelines: the model writes a Python script, and Hermes generates auto-stub modules whose functions call back into the parent process's real tool registry over RPC — so a fifty-call pipeline costs one inference turn and intermediate outputs never enter the context window.

  • Server: _rpc_server_loop (tools/code_execution_tool.py:652) runs on a thread in the parent process. Per request, in order: constant-time token check via secrets.compare_digest (tools/code_execution_tool.py:709), tool allow-list, per-execution call limit, terminal blocked-params strip, then dispatch through the standard model_tools.handle_function_call(...) with stdout/stderr silenced (tools/code_execution_tool.py:744).
  • Transports: Unix domain socket by default; TCP on 127.0.0.1 for Windows; a file-based request/response transport for remote sandbox backends (tools/code_execution_tool.py:1355, tools/code_execution_tool.py:576).
  • Child env: only HERMES_RPC_SOCKET + HERMES_RPC_TOKEN are handed over; everything else is scrubbed (tools/code_execution_tool.py:1435, allow-list at tools/code_execution_tool.py:147).
  • Budget interaction: execute_code iterations are refunded to the IterationBudget (agent/iteration_budget.py:28) — programmatic turns are free.

Hooks, events, middleware — four distinct surfaces

  1. Plugin lifecycle hooks — the main surface. Allow-list VALID_HOOKS (hermes_cli/plugins.py:156) spans tool, LLM, API, session, subagent (subagent_start/stop), gateway, approval, transcription and Kanban events. Front door: invoke_hook() (hermes_cli/lifecycle.py:11), which fires first-party observability before plugins; has_hook() is the cheap short-circuit on every hot call site. Notably, pre_gateway_dispatch runs before auth so plugins can handle unauthorized senders, and slash-command observation deliberately excludes the running-agent intercept path so a hostile plugin cannot take away /stop (hermes_cli/plugins.py:340).
  2. Plugin event bus — async and queued, distinct from hooks: PluginManager.subscribe() (hermes_cli/plugins.py:3265), bounded queue, single ordered daemon worker, recursion-depth cap (hermes_cli/plugins.py:5270).
  3. Middleware — "observer hooks report what happened; middleware can change what happens" (hermes_cli/middleware.py:3). Kinds: tool_request, tool_execution, llm_request, llm_execution; applied in the tool path at agent/tool_executor.py:540.
  4. Shell hooks + gateway hook registry — a hooks: block in cli-config.yaml bridges shell scripts onto the plugin hook manager with first-use consent and shell=False execution (agent/shell_hooks.py:1); separately, the gateway discovers filesystem hooks from ~/.hermes/hooks/*/HOOK.yaml (gateway/hooks.py:54) whose errors never block the pipeline.

Cross-cutting: identity propagation

gateway/session_context.py replaced process-global os.environ["HERMES_SESSION_*"] with ContextVars precisely because concurrent gateway messages were overwriting each other's routing identity (gateway/session_context.py:11). A _UNSET sentinel distinguishes "never set here" (fall back to env for CLI/cron) from "explicitly cleared" (gateway/session_context.py:41).

The consequences shape the whole codebase: _handle_message resets session vars on entry (gateway/run.py:16255); every thread hand-off copies the context explicitly — executor offload (gateway/run.py:24176), delegation fan-out (tools/delegate_tool.py:3925), MoA workers (agent/moa_loop.py:850); and async_delivery_supported() (gateway/session_context.py:482) is what lets delegate_task choose background vs inline per surface.

Transferable idea. "Routing identity in ContextVars with explicit copies at every thread boundary" is one of the cleanest solutions in the repo to the classic multi-tenant-agent identity-leak problem — see Transferables.
