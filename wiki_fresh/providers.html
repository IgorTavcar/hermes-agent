Providers & Subscription Tiers

Hermes speaks to ~40 inference providers through four API dialects. The interesting part is the "subscription contracts" — consumer subscriptions (Claude Pro/Max, ChatGPT Plus/Pro, SuperGrok, GitHub Copilot, Qwen, MiniMax Coding Plan) reused as agent inference, each requiring its own OAuth flow, token store, refresh logic, and — for some — client-identity spoofing to pass the vendor's edge. This page documents each one, one by one, grounded in the auth code.

Unification happens in provider_catalog.py (hermes_cli/provider_catalog.py:83), which tags each slug with a desktop tab derived purely from its auth type. The four API dialects (api_mode): chat_completions (OpenAI wire), anthropic_messages, codex_responses (OpenAI Responses API), bedrock_converse. See LLM Kernels for how each dialect actually executes.

The credential pool (multi-account rotation)

Every provider gets a pool keyed by slug (agent/credential_pool.py:164), auth types oauth/api_key, sources like manual, env:<VAR>, claude_code, hermes_pkce, device_code, gh_cli, qwen-cli. Rotation strategies are fill_first | round_robin | random | least_used. Per-provider refresh dispatch lives in _refresh_entry_impl (agent/credential_pool.py:1365); Codex and xAI refreshes are wrapped in a cross-process auth.json flock because their refresh tokens are single-use (agent/credential_pool.py:1313).

Claude Pro / Max — the deepest subscription integration

Slug anthropic, base https://api.anthropic.com, anthropic_messages dialect. A token's prefix decides its auth: sk-ant-api* → API key (x-api-key); sk-ant-*/JWT/cc-* → OAuth (Bearer) (agent/anthropic_adapter.py:414). Resolution priority runs env vars → the Claude Code credential store (Keychain / ~/.claude/.credentials.json, refreshed if expired) → the credential pool (agent/anthropic_adapter.py:1391).

OAuth client & refresh (agent/anthropic_adapter.py:1496):

client_id = "9d1c250a-e61b-44d9-88ed-5944d1962f5e"
_OAUTH_TOKEN_URLS = ["https://platform.claude.com/v1/oauth/token",
                     "https://console.anthropic.com/v1/oauth/token"]
_OAUTH_TOKEN_USER_AGENT = "axios/1.7.9"    # deliberate spoof

The axios/1.7.9 UA is deliberate and documented: Anthropic rate-limits (429) any token-endpoint request whose UA starts with claude-code/, and the real CLI exchanges the code with a bare axios client (agent/anthropic_adapter.py:1506). Hermes writes refreshed tokens back to ~/.claude/.credentials.json atomically at mode 0600, preserving scopes because Claude Code ≥2.1.81 gates on the presence of user:inference (agent/anthropic_adapter.py:1246).

How Hermes presents itself as Claude Code at runtime (agent/anthropic_adapter.py:908): user-agent: claude-code/<detected-cli-version> (external, cli), x-app: cli, the OAuth-only beta headers, a prepended "You are Claude Code…" system block, product-name scrubbing (Hermes Agent→Claude Code, Nous Research→Anthropic), and tool-name rewriting to the double-underscore mcp__ form — a single-underscore name trips Anthropic's subscription-billing classifier into an HTTP 400 (agent/anthropic_adapter.py:2971). Usage is read from /api/oauth/usage, mapping five_hour/seven_day windows plus extra-usage credits (agent/account_usage.py:751).

Setup: hermes model → Anthropic → "Claude Pro/Max subscription (OAuth login)" runs claude setup-token as a subprocess and prefers linking the Claude Code store over copying a token (hermes_cli/model_setup_flows.py:3115). Hermes also ships its own PKCE flow — hermes auth add anthropic --type oauth — landing tokens in the pool with source manual:hermes_pkce (agent/anthropic_adapter.py:1535).

GUI mis-tab (worth knowing). The registry marks anthropic auth_type="api_key" even though OAuth is its primary subscription path, so it lands on the desktop "keys" tab; a hand-written claude-code accounts card compensates (hermes_cli/auth.py:396).

ChatGPT / Codex subscription (openai-codex)

Base https://chatgpt.com/backend-api/codex, codex_responses dialect, oauth_external. Login is a device-code flow (hermes_cli/auth.py:8204):

CODEX_OAUTH_CLIENT_ID = "app_EMoamEEZ73f0CkXaXp7hrann"
CODEX_OAUTH_TOKEN_URL = "https://auth.openai.com/oauth/token"
CODEX_OAUTH_USER_AGENT = f"hermes-cli/{__version__}"

The user opens auth.openai.com/codex/device, enters the code, and Hermes polls, then exchanges the authorization code. Tokens live at auth.json → providers.openai-codex.tokens; Hermes only reads ~/.codex/auth.json, never writes it (hermes_cli/auth.py:3830). Refresh has a 429→CODEX_RATE_LIMITED path that keeps credentials valid, and a bespoke refresh_token_reused diagnostic when Codex CLI/VS Code consumed the single-use token (hermes_cli/auth.py:3874).

Edge-spoofing is required to pass Cloudflare in front of the Codex backend (agent/auxiliary_client.py:1214):

"User-Agent": "codex_cli_rs (Hermes Agent)",
"originator": "codex_cli_rs",
# + ChatGPT-Account-ID decoded from the OAuth JWT's chatgpt_account_id claim

Non-residential IPs without an allowed originator get 403 cf-mitigated: challenge. Models are fetched live from /codex/models (hermes_cli/codex_models.py:122); the fallback list includes the gpt-5.6-*/gpt-5.x-codex families. A banked-reset feature (/usage reset) redeems a credit to restore full 5h+weekly limits (agent/account_usage.py:587). Multi-account: hermes auth add openai-codex creates an independent pool entry per ChatGPT account rather than collapsing them (hermes_cli/auth_commands.py:310).

xAI Grok OAuth — SuperGrok / X Premium+ (xai-oauth)

Base https://api.x.ai/v1, codex_responses transport, oauth_external. OIDC device-code flow (hermes_cli/auth.py:8134):

XAI_OAUTH_ISSUER = "https://auth.x.ai"
XAI_OAUTH_CLIENT_ID = "b1a00492-073a-47ea-816f-4c329264a828"
XAI_OAUTH_SCOPE = "openid profile email offline_access grok-cli:access api:access"
XAI_ACCESS_TOKEN_REFRESH_SKEW_SECONDS = 3600   # tokens ~6h; refresh 1h early

Refresh re-validates the cached token_endpoint against xAI's domain on every use — an auth.json written by an older Hermes could carry a non-xAI endpoint that would receive every future refresh token in plaintext (hermes_cli/auth.py:4961). A 403 gets a dedicated xai_oauth_tier_denied message rather than a re-login prompt: xAI may restrict API/OAuth use to specific SuperGrok tiers despite an active in-app subscription (hermes_cli/auth.py:4987). Unlike the others, xAI OAuth uses no spoofing — Hermes identifies honestly as Hermes-Agent/<version> (tools/xai_http.py:95). Setup: hermes model → xAI Grok → OAuth, or hermes auth add xai-oauth.

GitHub Copilot — subscription via GitHub OAuth → short-lived JWT

Base https://api.githubcopilot.com, dialect resolved per model (GPT-5+/Codex → responses, Claude → anthropic, rest → chat). Only gho_/github_pat_/ghu_ tokens are accepted — classic ghp_ is rejected (hermes_cli/copilot_auth.py:41). The device-code login uses VS Code's GitHub App client id, deliberately, because the old opencode App id produces tokens that can't be exchanged for Copilot JWTs (hermes_cli/copilot_auth.py:34):

COPILOT_OAUTH_CLIENT_ID = "Iv1.b507a08c87ecfe98"

The "subscription contract" is the token exchange (hermes_cli/copilot_auth.py:480): a GET to copilot_internal/v2/token with Editor-Version: vscode/1.104.1 returns a short-lived, semicolon-separated token plus the enterprise API endpoint, cached in-process and at ~/.hermes/.copilot_jwt.json, refreshed 120 s before expiry. Requests spoof the editor: Editor-Version: vscode/1.104.1, User-Agent: HermesAgent/1.0, Copilot-Integration-Id: vscode-chat, x-initiator: agent|user (hermes_cli/copilot_auth.py:683). The sibling copilot-acp delegates auth entirely to a local copilot --acp subprocess logged in via copilot /login (hermes_cli/model_setup_flows.py:1998).

Qwen OAuth — borrowed Qwen CLI subscription (qwen-oauth)

Base https://portal.qwen.ai/v1. Hermes has no login flow of its own: it reads ~/.qwen/oauth_creds.json written by qwen auth qwen-oauth and refuses with an instruction if absent (hermes_cli/auth.py:2664). Refresh POSTs to chat.qwen.ai/api/v1/oauth2/token with client_id="f0304373b74a44d2b584a3fb70ca9e56", and writes the rotated pair back to the Qwen CLI's own file at 0600. Headers spoof the Qwen Code CLI: User-Agent: QwenCode/0.14.1 … plus DashScope headers (run_agent.py:335).

MiniMax OAuth — Coding Plan (minimax-oauth)

anthropic_messages dialect against .../anthropic. PKCE user-code flow (hermes_cli/auth.py:8611): client_id="78257093-7e40-4613-99e0-527b14b39113", scope "group_id profile model.completion", region-aware portals (global/CN). Tokens land in auth.json → providers.minimax-oauth; setup via hermes model → MiniMax → OAuth or hermes auth add minimax-oauth --region cn|global.

Nous Portal — first-party subscription (nous)

Device-code OAuth against portal.nousresearch.com, client_id="hermes-cli", scope inference:invoke (hermes_cli/auth.py:250). The access token doubles as the inference JWT, validated by scope + TTL before use. A subscription_required error at login prints the billing URL; entitlement/feature mapping lives in hermes_cli/nous_subscription.py. Cross-profile sharing goes through <root>/shared/nous_auth.json. Nous is dual-wire — anthropic/* catalog ids route to /v1/messages, everything else to /v1/chat/completions (hermes_cli/providers.py:691).

Antigravity & the plan-key tiers

Google Antigravity is not a provider in this tree. It exists only as an optional skill wrapping the local agy CLI — the skill's own note says it "does not wrap a network API, so there is nothing to authenticate from Hermes itself" (optional-skills/autonomous-ai-agents/antigravity-cli/SKILL.md:17).

Several vendors sell subscription plans that are consumed through a plain API key with special endpoint routing, so Hermes treats them as api_key providers:

  • Z.AI / GLM Coding Plan: four official endpoints probed in priority order (a key that works on one returns "Insufficient balance" on another), winner cached by a key hash (hermes_cli/auth.py:732).
  • Kimi / Moonshot Coding Plan: sk-kimi- keys auto-route to api.kimi.com/coding; on that host Hermes sends honest attribution headers rather than a spoof, at the Kimi team's request (agent/anthropic_adapter.py:875).
  • Alibaba Coding Plan, StepFun Step Plan, OpenCode Go ($10/mo key) — all dedicated endpoints keyed by a plan-tier API key.

Setup surfaces

hermes model builds the provider picker from CANONICAL_PROVIDERS folded through groups (e.g. the "openai" group holds both openai-codex and openai-api); every subscription provider has a bespoke flow, everything else falls through to a generic API-key flow (hermes_cli/main.py:3913). hermes auth covers add | list | remove | reset | status | logout, with the OAuth-capable set fixed at {anthropic, nous, openai-codex, xai-oauth, qwen-oauth, minimax-oauth} (hermes_cli/auth_commands.py:37). Removal dispatches to per-source teardown steps that decide suppress-vs-delete: Claude Code's file is suppressed, never deleted; Hermes-PKCE tokens are deleted outright (agent/credential_sources.py:202). The single choke point for saving/removing an API key across the three stores (.env, pool, config mirror) is hermes_cli/credential_lifecycle.py, whose contract only prunes env:-sourced entries and never touches OAuth blocks.

graph TD;
  U[hermes model / hermes auth add]-->F{provider type};
  F-->|API key|K[save to ~/.hermes/.env + config mirror];
  F-->|subscription OAuth|O[device-code / PKCE / borrow CLI creds];
  O-->S[tokens -> auth.json providers.slug + credential_pool];
  S-->R[per-provider refresh: single-use flock for codex/xai];
  R-->H[runtime: spoof client identity where required];
  H-->I[inference call];
  K-->I;
Where Hermes actively impersonates another client. Only five: Anthropic OAuth (claude-code UA + system prompt + product scrubbing + mcp__ renaming + axios/1.7.9 at the token endpoint), Codex (codex_cli_rs originator), Copilot (vscode/1.104.1 + GitHubCopilotChat), and Qwen (QwenCode/0.14.1). xAI, Nous, MiniMax and every API-key provider identify honestly as Hermes.
