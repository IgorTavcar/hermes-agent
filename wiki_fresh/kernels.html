LLM Kernels & Adapters

The "kernel" of the agentic loop is the layer where inference, tool-calling and streaming actually execute — per provider dialect. Hermes deliberately has no single LLM-client class: it splits the job into declarative provider profiles, format-converting transports, an imperative client-lifecycle + streaming layer, and a relay wrapper around every physical attempt. This page documents each tier, each dialect's exact conversion and streaming mechanics, and where the loop invokes them.

The four-tier shape

TierOwnsWhere

Client lifecycle + streaming (imperative)SDK client construction/caching/abort, streaming loops, delta assemblyrun_agent.py:5311, agent/chat_completion_helpers.py:3833, agent/codex_runtime.py:1038

The abstraction boundary is stated in the transport ABC's own docstring: "A transport owns the data path for one api_mode: convert_messages → convert_tools → build_kwargs → normalize_response. It does NOT own: client construction, streaming, credential refresh, prompt caching, interrupt handling, or retry logic. Those stay on AIAgent." (agent/transports/base.py:1). Four transports register: ChatCompletionsTransport (agent/transports/chat_completions.py:234), AnthropicTransport (agent/transports/anthropic.py:13), ResponsesApiTransport (agent/transports/codex.py:287), BedrockTransport (agent/transports/bedrock.py:15).

Which SDKs are wrapped

  • openai==2.24.0 — core dependency (pyproject.toml:40), used for both chat.completions and responses.
  • anthropic==0.87.0 — optional [anthropic] extra, lazily imported (agent/anthropic_adapter.py:56).
  • boto3==1.42.89 — optional [bedrock] extra (agent/bedrock_adapter.py:64).
  • httpx[socks]==0.28.1 — used raw for the hand-rolled Gemini native client and for custom http-client injection (keepalives, Entra bearer hooks).
  • google-auth — token minting only for Vertex, never inference (agent/vertex_adapter.py:36). There is no Google GenAI SDK anywhere.
  • nemo-relay — the observability wrapper (agent/relay_runtime.py:1609).

Beyond the real SDKs, a family of duck-typed "fake OpenAI clients" all expose .chat.completions.create(**kwargs) so ~45 loop call sites never branch: GeminiNativeClient (agent/gemini_native_adapter.py:1045), CopilotACPClient (agent/copilot_acp_client.py:450), MoAClient (agent/moa_loop.py:2313), and the auxiliary Codex/Anthropic/Bedrock shims in agent/auxiliary_client.py:1902 ff. Even ToolCall duck-types the OpenAI SDK via @property function → self (agent/transports/types.py:45).

Dialect: chat_completions (OpenAI-compatible)

  • Message conversion is a security/compat boundary, not a format converter: convert_messages() (agent/transports/chat_completions.py:244) deletes Hermes-internal and foreign-dialect keys strict providers 400 on — codex_reasoning_items, tool_name, api_content, timestamps, any _-prefixed key — keeping Gemini's extra_content thought signatures only for Gemini-family models (agent/transports/chat_completions.py:218).
  • System prompt stays at messages[0]; the role swaps system → developer for GPT-5/Codex families (agent/transports/chat_completions.py:501).
  • Request quirks come from three profile hooks — prepare_messages(), build_extra_body(), build_api_kwargs_extras() (providers/base.py:133); a legacy ~20-boolean flag path survives only for unregistered providers (agent/transports/chat_completions.py:498).
  • Streaming: chat.completions.create(stream=True, stream_options={"include_usage": True}), deltas assembled in _call_chat_completions (agent/chat_completion_helpers.py:3833). Tool-call accumulation: name is assigned, arguments are concatenated — MiniMax resends full names, Ollama reuses indices (agent/chat_completion_helpers.py:4220). After the stream: per-call JSON validity check, argument repair, and distinct handling of "truncated by length" vs "stream dropped mid-tool-call". The streamed result is repackaged into a non-streaming-shaped SimpleNamespace so the loop body never notices (agent/chat_completion_helpers.py:4446).
  • Usage: canonical normalization in agent/usage_pricing.py:1271, handling Anthropic-style names leaking through OpenAI-compat proxies, DeepSeek's top-level cache counters, and reasoning-token buckets.

Dialect: anthropic_messages

  • Conversion: convert_messages_to_anthropic() (agent/anthropic_adapter.py:2785) hoists system messages out into the top-level system, then runs six post-passes: strip orphaned tool blocks → merge consecutive roles → ensure a leading user turn → manage thinking signatures → evict old screenshots → scrub blank text blocks.
  • Tools: function.parameters → input_schema, with nullable-union stripping (agent/anthropic_adapter.py:1789).
  • Client: build_anthropic_client() auth-branches per endpoint kind — API key, bearer, or the Claude-Code OAuth identity described on Providers & Tiers — always with max_retries=0 and a 900 s timeout (agent/anthropic_adapter.py:793).
  • Streaming: client.messages.stream() as a context manager; Hermes iterates SDK events itself (content_block_start/delta, thinking deltas) and takes the final message from get_final_message() (agent/chat_completion_helpers.py:4464). A parallel AnthropicStreamAccumulator rebuilds the message from raw SSE — including input_json_delta partial-JSON accumulation — when the relay modified the output (agent/relay_llm.py:810).
  • Parse-back: content blocks split into text / thinking / tool_use, stop reasons mapped (tool_use→tool_calls, max_tokens→length, …), and the OAuth mcp__ tool-name prefix reversed by registry lookup (agent/transports/anthropic.py:80).
Interleaved thinking ordering. When a turn interleaves signed thinking with tool_use, the parallel lists lose cross-type ordering and replaying in the wrong order triggers HTTP 400. The transport therefore captures a verbatim order-preserving ordered_blocks list — emitted only when both signed thinking and tool_use are present — and replays it as-is (agent/transports/anthropic.py:97). Signature lifecycle on replay: strip for third-party endpoints, keep signed only on the latest assistant message for direct Anthropic, with Nous Portal explicitly exempted (agent/anthropic_adapter.py:2512).

Dialect: codex_responses (OpenAI Responses API)

  • Conversion: system messages become the top-level instructions; assistant tool calls become function_call items and tool results become function_call_output items — with multimodal parts allowed in outputs (agent/codex_responses_adapter.py:410).
  • Tools flatten to {type:"function", name, description, strict:false, parameters} (agent/codex_responses_adapter.py:341).
  • Streaming is deliberately low-level: Hermes calls responses.create(stream=True) raw instead of the SDK's high-level responses.stream(), because the consumer Codex backend drifts response.completed.response.output to null and the SDK's reconstruction throws mid-iteration. The final object is assembled only from response.output_item.done events (agent/codex_runtime.py:1349, rationale at agent/codex_runtime.py:955; event consumer at agent/codex_runtime.py:1038).
  • Reasoning continuity: reasoning items with encrypted_content are captured and replayed as input items, guarded by a per-item issuer filter and a session kill switch, so encrypted reasoning never replays cross-endpoint (agent/codex_responses_adapter.py:1458).
  • Always store: false; tools omitted entirely when empty (the SDK iterates it without a None guard); Codex session headers and xAI conversation ids stamped per request (agent/transports/codex.py:337).

Dialect: Gemini native (raw httpx, no SDK)

When the base URL is native generativelanguage.googleapis.com/v1beta (not the /openai subpath), create_openai_client returns GeminiNativeClient — a raw-httpx client masquerading as the OpenAI SDK (agent/agent_runtime_helpers.py:2497, agent/gemini_native_adapter.py:1045).

  • System messages become a separate systemInstruction; roles map assistant→model, tool results become functionResponse parts; alternation repair refuses to fuse human text into a functionResponse turn, interposing a placeholder model turn instead (agent/gemini_native_adapter.py:450).
  • Tools become functionDeclarations with schema sanitization (agent/gemini_schema.py:134); tool_choice maps to functionCallingConfig.mode AUTO/ANY/NONE.
  • Streaming is hand-rolled SSE against :streamGenerateContent?alt=sse. Gemini re-sends the whole args object each event, so Hermes diffs and emits only the incremental suffix (agent/gemini_native_adapter.py:889).
  • Gemini-3 thoughtSignatures round-trip via extra_content, with a literal "skip_thought_signature_validator" sentinel for cross-provider replays (agent/gemini_native_adapter.py:353).

Vertex AI is not a separate dialect — agent/vertex_adapter.py only mints a bearer token and builds the OpenAI-compatible Vertex URL (agent/vertex_adapter.py:190).

Dialect: bedrock_converse

Pure boto3 (agent/transports/bedrock.py:1): tools become toolSpec.inputSchema.json (agent/bedrock_adapter.py:488); streaming iterates the boto3 event stream, accumulating tool-argument JSON as a string and parsing at contentBlockStop (agent/bedrock_adapter.py:845). The preferred path for Claude-on-Bedrock is not Converse at all — it is anthropic.AnthropicBedrock, for full parity on prompt caching, adaptive thinking and the 1M-context beta (agent/anthropic_adapter.py:949).

Where the loop invokes the kernels

Per inner-loop iteration: build_api_kwargs() (agent/chat_completion_helpers.py:1825) → cache markers re-applied per provider per retry attempt → _perform_api_call() (agent/conversation_loop.py:3019) — streaming-preferred via _interruptible_streaming_api_call, else relay_llm.execute — wrapped in LLM-execution middleware → transport.validate_response() → transport.normalize_response() → build_assistant_message().

The main loop is fully synchronous. Requests run on a daemon worker thread the caller polls for interrupts and staleness; cron and delegated-child contexts run inline instead, to avoid nested-thread-pool deadlocks (agent/chat_completion_helpers.py:1002). Async exists only in the auxiliary layer, as asyncio.to_thread wrappers.

Client lifecycle safety. Per-request clients exist because of a real memory-corruption class: a watchdog thread must never close() a client whose TLS socket another thread is reading. Stranger threads only shutdown(SHUT_RDWR) the socket; owner threads do the SDK close; both OpenAI and Anthropic request clients sit in a single-slot warm cache with in_use/poisoned flags (run_agent.py:5429, run_agent.py:5344).

Retries, timeouts, rate limits, fallback

  • SDK retries are off everywhere (max_retries=0) — the SDK default ignores Retry-After and double-retries inside Hermes's own loop (run_agent.py:5331, agent/anthropic_adapter.py:858). All retry/backoff/rotation/fallback lives in the outer retry loop.
  • Three retry layers: SDK (disabled) → stream-level (HERMES_STREAM_RETRIES, default 2) → turn-level with jittered backoff (5–120 s), Retry-After parsing, and provider-specific ladders (agent/retry_utils.py:90).
  • Timeouts: per-provider request_timeout_seconds; streaming read timeout auto-raised for local endpoints (vLLM/Ollama prefill can take minutes) and reasoning models; stale-stream watchdogs with per-family floors and a cross-turn stale-streak circuit breaker (agent/chat_completion_helpers.py:3836).
  • Rate limits: headers captured on every response (run_agent.py:4043); account-level 429 distinguished from upstream-capacity 429 by inspecting the 429's own headers; credential-pool rotation runs before model fallback (run_agent.py:6423).
  • Fallback chain: try_activate_fallback() arms an exponential primary cooldown, walks the chain skipping identical backends, and rebuilds the client through the same central router the auxiliary layer uses (agent/chat_completion_helpers.py:2427).

Prompt caching

  • Anthropic-style breakpoints: a 4-marker budget — static system prefix, whole system, then the last N cacheable messages — planned by build_prompt_cache_plan() (agent/prompt_caching.py:385). Native layout puts markers on inner content blocks; OpenAI-wire proxies get envelope markers. Re-decorated per retry attempt so a mid-turn failover re-plans for the new provider (agent/conversation_loop.py:1490).
  • prompt_cache_key (OpenAI/xAI/Codex routing hint): one hash — pck_<sha256[:24]> over scope + instructions + sorted tools — with cron's per-fire timestamp stripped from the scope and a rotation-stable logical scope resolved from the compression lineage root (agent/transports/codex.py:143, agent/prompt_cache_scope.py:67).
  • Sticky routing keys: OpenRouter and Nous put session_id in the body; Codex mirrors it into x-client-request-id, xAI into x-grok-conv-id (agent/transports/codex.py:627).

Tool schemas: from registry to every dialect

Schemas are hand-written dicts, self-registered at import time — there is no signature introspection anywhere in this path:

registry.register(name="read_file", toolset="file", schema=READ_FILE_SCHEMA,
                  handler=_handle_read_file, check_fn=_check_file_reqs, ...)

(tools/file_tools.py:2809.) The pipeline: toolsets.py composes toolsets (toolsets.py:107) → get_tool_definitions() memoizes on registry generation + config mtime (model_tools.py:323) → ToolRegistry.get_definitions() filters by check_fn and applies dynamic_schema_overrides — which is how delegate_task's description reflects live concurrency config (tools/registry.py:1018) → a cross-provider hardening pass renames illegal property keys, strips $ref siblings and top-level combinators, and collapses nullable unions (tools/schema_sanitizer.py:120), with the inverse rename applied at dispatch so handlers see original names (model_tools.py:831). Each transport then converts that one canonical list to its dialect (identity, input_schema, flat Responses shape, toolSpec.inputSchema.json, functionDeclarations).
